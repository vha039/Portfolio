Way of working

AI in practical development work

I use language models and coding agents every day in analysis and development. I define the tasks narrowly, set requirements for how the results are checked, and take responsibility myself for architecture, integration and review of the outcome.

Well-defined tasks and domain requirements

#

In the forecasting project some of the checks are domain rules: a forecast may only use information that would have been known when it was made, and no variable may disappear without it becoming visible. I carried out the phase II architecture redesign with coding agents in one month.

The work has a fixed structure: lasting project instructions with scope, constraints and evidence requirements, handovers between runs, and one integrator who merges the changes.

Architecture responsibility and integration in the forecasting project

A plan that was too large, stopped and simplified

#

The redesign with coding agents started from a far too extensive plan. It would have given a sound core architecture for a large company selling forecasts as a service, with a lot of infrastructure our codebase did not need.

I noticed it fairly early and stopped the implementation. Starting from the partly implemented code, I re-planned, designed a tightly scoped minimum viable product (MVP) and implemented it in full.

The choice in the forecasting project

Compatibility before tidy code

#

In the budget work I used AI assistants in development, refactoring and troubleshooting. A suggestion had to be assessed against established formulas, macros and workflow. Tidy code was not enough if a calculation or a familiar Excel behaviour changed.

AI super user at the hospital

#

For about three years I have been a registered AI super user at Oslo University Hospital. In the role I answer technical questions about AI in a Teams channel.

Strict LLM Composer

#

Strict LLM Composer is a system I have built for text that must stick to documented facts. Lasting source facts are kept separate from task requirements and new drafts. The models can formulate text, but cannot create a degree, a result or a responsibility that the sources do not support.

I check the facts and the finished drafts and personally approve everything that is used. This is a personal project, not a deliverable to the hospital.

Scope and way of working

#

I have used language models extensively since GPT-3. Today I use models and coding agents from several providers every day, with more than a billion tokens a month.

A short professional clarification needs little structure. When the work touches several files or calculations, I define what may be changed, which sources apply and which dependencies must be preserved. The models can investigate, suggest, write and check. I decide whether the answer addresses the right problem, whether the assumptions hold and whether the result can be used.
